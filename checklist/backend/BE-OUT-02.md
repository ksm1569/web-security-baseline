# BE-OUT-02 서버가 태그를 살려 보여 줄 HTML을 허용 목록 기반 sanitizer로 거르는가

- **적용**: 공통
- **위험**: 공격자가 게시글이나 1:1 문의 본문에 `<img src=x onerror=...>` 같은 태그를 넣어 저장하면 그 글을 연 사용자와 관리자의 브라우저에서 스크립트가 실행되어, 그 사람 권한으로 글을 쓰거나 설정을 바꾸고 화면의 개인정보를 가져간다.
- **기준**: 사용자나 외부 시스템이 보낸 HTML은 서버에서 HTML을 파싱해 허용 목록에 있는 태그·속성·URL 스킴만 남기는 sanitizer 라이브러리나 프레임워크 기능을 거치고, 그 결과를 다시 디코딩하지 않고 내보낸다.\
  태그 없이 글자로 보여 주면 되는 값은 [BE-OUT-01](BE-OUT-01.md)대로 이스케이프한다.\
  브라우저에서 HTML을 만들거나 화면에 넣는 코드(마크다운 렌더링, `innerHTML` 등)는 [FE-01](../frontend/FE-01.md)에서 본다.
  - 허용 목록에 `script` 태그와 `on`으로 시작하는 속성이 없다.
  - `href`·`src`·`action`처럼 URL을 받는 속성은 `http:`·`https:`처럼 정해 둔 스킴만 허용한다.
  - `iframe`을 허용한다면 `src`를 정해 둔 도메인으로 제한하고 `srcdoc`은 허용하지 않는다.
  - 서버가 마크다운·BBCode를 HTML로 바꾼다면 바꾼 결과를 거른다.
  - 출력할 때 거른다면 그 값이 HTML로 그려지는 모든 경로가 sanitizer를 지난다.
  - 저장할 때 거른다면 사용자나 외부에서 온 HTML을 그 컬럼에 넣는 모든 경로가 sanitizer를 지나고, sanitizer를 넣기 전에 쌓인 데이터도 다시 거른다.
  - 둘 다 거른다면 위 두 조건 중 하나를 만족하면 된다.
- **하지 말 것**:
  - 정규식이나 문자열 치환으로 `<script>`·`javascript:`·`onerror` 같은 단어를 지우는 필터를 직접 만들기.\
    한 번만 지우면 `<scr<script>ipt>`에서 가운데가 지워진 뒤 `<script>`가 남는다.\
    `onerror`·`onload`를 막아도 `<details open ontoggle=alert(1)>`처럼 막는 목록에 없는 이벤트 속성으로 실행된다.\
    `href`의 `javascript:`는 `&#106;avascript:`처럼 엔티티로 쓰거나 중간에 탭을 넣어도 브라우저가 풀어서 읽으므로 누르면 실행된다.
  - 에디터나 브라우저에서만 거르기.\
    에디터가 보내기 전에 거르면 저장 요청을 직접 보내서 건너뛴다.\
    브라우저가 화면에 넣기 전에 거르면 앱 웹뷰나 이 값을 받아 가는 다른 시스템은 거르지 않은 HTML을 받는다.
  - 에디터 본문이 망가진다며 게시글 저장 URL을 XSS 필터 예외에 넣고 끝내기.\
    예외에 들어간 URL로 오는 값은 아무 검사 없이 저장된다.
  - 필터가 `&lt;`로 바꿔 둔 본문을 unescape로 되돌려 출력하기.\
    공격자가 보낸 태그도 함께 되돌아오므로 필터가 없는 것과 같다.\
    sanitizer 뒤에 디코딩해도 마찬가지다.\
    sanitizer가 글자로 보고 넘긴 `&lt;script&gt;`가 태그로 바뀐다.
  - 유튜브 영상을 넣으려고 `iframe`의 `src`를 아무 제한 없이 허용하기.\
    `<iframe src="javascript:...">`는 누르지 않아도 글이 보이는 페이지와 같은 출처에서 실행된다.\
    스킴을 막아도 도메인을 열어 두면 공격자가 만든 가짜 로그인 화면이 글 안에 뜬다.\
    `src`를 제한해도 `srcdoc`을 함께 허용하면 그 안의 스크립트가 같은 출처에서 실행된다.
- **확인 방법**: 아래 단계에서 미통과가 하나라도 나오면 이 항목은 미통과다.
  1. 태그를 살려 보여 주는 입력을 고른다.\
     게시글·공지·상품 설명 에디터, 1:1 문의, 팝업 템플릿, 서버가 HTML로 바꾸는 마크다운 입력 같은 곳이다.\
     관리자만 쓰는 에디터도 고른다.\
     [BE-OUT-01](BE-OUT-01.md) 확인 방법 5단계에서 넘어온, 태그를 살려 보여 줄 HTML을 이스케이프하지 않고 내보내는 곳도 여기서 본다.\
     고른 입력은 점검 기록의 근거 칸에 적는다.\
     [FE-01](../frontend/FE-01.md)은 이 기록으로 서버가 거른 필드인지 확인한다.\
     이런 입력이 없으면 해당없음이다.
  2. 고른 입력마다 화면의 에디터를 거치지 않고 저장 요청을 직접 보낸다.\
     운영 환경에서 한다면 관리자에게 미리 알리고 점검이 끝나면 지운다.\
     취약하면 시험 글을 연 사람의 브라우저에서 alert 창이 뜬다.\
     개발자 도구 Network 탭에서 저장 요청을 cURL로 복사하고 글 내용 필드 값만 아래 값으로 바꿔 보낸다.\
     `Content-Type`이 `application/x-www-form-urlencoded`면 값을 URL 인코딩한다.\
     `&`를 그대로 두면 값이 거기서 잘린다.\
     `multipart/form-data`면 그대로 넣고, JSON이면 `"`를 `\"`로 바꾼다.\
     값마다 글을 따로 저장한다.\
     요청이 막히거나 저장이 거부된 값은 3단계 판정에 쓰지 않고 4단계 코드 확인으로 판정한다.
     - `<img src=x onerror=alert(1)>`
     - `<details open ontoggle=alert(1)>x</details>`
     - `<scr<script>ipt>alert(1)</scr</script>ipt>`
     - `<a href="&#106;avascript:alert(1)">x</a>`
     - `<iframe srcdoc="<script>alert(1)</script>"></iframe>`
     - 마크다운 입력이면 `[x](javascript:alert(1))`
  3. 저장한 글이 나오는 화면의 응답 원문에서 넣은 값을 찾는다.\
     응답 원문은 curl이나 개발자 도구 Network 탭의 응답 본문으로 본다.\
     글 보기뿐 아니라 목록 미리보기, 관리자 화면, 수정·답변 화면처럼 저장된 글을 다시 불러오는 화면도 본다.\
     SPA라면 글 내용을 내려 주는 API 응답을 Preview 탭이나 `jq -r`로 꺼내 본다.\
     JSON 원문의 `\u003c`·`\u003d`는 JSON 문자열 표기라 풀면 `<`·`=`다.\
     넣은 값이 `&lt;`로 바뀌어 글자로 나오면 그 자리는 통과다.\
     단, 수정 화면처럼 그 값이 에디터에 서식대로 다시 뜨는 자리는 엔티티나 `\u003c` 같은 표기를 풀고 아래 조건으로 본다.\
     에디터 초기화 코드가 `textarea`·숨긴 요소·`<script>` 안의 값을 꺼내 HTML로 넣기 때문이다.\
     그 코드가 안전한지는 FE-01에서 보고, 여기서는 서버가 거르지 않은 HTML을 내보냈는지만 본다.\
     화면을 열었을 때 alert 창이 뜨면 그 값이 나온 자리의 표기를 풀고 아래 조건으로 본다.\
     조건에 걸리면 미통과고, 걸리지 않으면 브라우저 코드가 원인이므로 FE-01에 적는다.\
     HTML 주석 안은 태그로 보지 않는다.\
     태그로 남은 곳에 다음 중 하나라도 있으면 미통과다.
     - `on`으로 시작하는 속성
     - 대소문자와 상관없이 `<script`
     - `iframe`의 `srcdoc`
     - 넣은 값에서 나온 `a` 태그의 `href` 중, 엔티티를 풀고 탭·줄바꿈과 앞뒤 공백·제어 문자를 뺀 값이 `javascript:`처럼 정해 두지 않은 스킴으로 시작하는 것
  4. 코드에서 값이 저장되고 화면으로 나가기까지를 따라간다.\
     다음 중 하나라도 해당하면 미통과다.
     - 그 HTML이 저장할 때도 출력할 때도 sanitizer 라이브러리나 프레임워크 기능을 거치지 않는다.\
       정규식이나 문자열 치환으로만 거르는 경우도 여기에 든다.
     - 필터나 sanitizer를 거친 값을 출력 전에 unescape·디코딩하거나 `&lt;`를 `<`로 되돌린다.
     - sanitizer가 `script` 태그, `on`으로 시작하는 속성, `iframe`의 `srcdoc`을 허용하거나, `iframe`의 `src`를 도메인 제한 없이 허용하거나, URL을 받는 속성의 스킴을 제한하지 않는다.\
       설정에 적힌 것과 라이브러리 기본값을 함께 본다.
     - 서버가 마크다운·BBCode를 HTML로 바꾸면서 바꾸기 전의 원문만 거른다.
  5. sanitizer가 도는 시점에 따라 그 컬럼의 경로를 모두 찾는다.\
     저장할 때와 출력할 때 모두 거른다면 두 갈래를 모두 보고, 두 갈래가 모두 미통과일 때만 미통과로 적는다.
     - 출력할 때 거른다면 그 값이 HTML로 그려지는 경로를 모두 찾는다.\
       글 보기, 목록 미리보기, 수정 화면의 에디터, 관리자 화면, 앱·외부 연동 API, RSS 같은 경로다.\
       sanitizer를 지나지 않는 경로가 하나라도 있으면 미통과다.
     - 저장할 때 거른다면 사용자나 외부에서 온 HTML을 그 컬럼에 넣는 경로를 모두 찾는다.\
       등록·수정 API, 관리자 등록, 엑셀 일괄 등록, 외부 연동, 배치 같은 경로다.\
       sanitizer를 지나지 않는 경로가 하나라도 있으면 미통과다.\
       sanitizer를 넣기 전에 쌓인 행이 있다면 그 행을 지금 쓰는 sanitizer로 다시 거른 작업(마이그레이션·배치)이 있었는지 확인한다.\
       그런 작업이 없었으면 미통과다.\
       있었는지 확인할 수 없으면 DB에서 그 컬럼을 대소문자 구분 없이 `<script`·`script:`·`srcdoc`과 정규식 `[[:space:]/"']on[a-z]+[[:space:]]*=`로 검색한다.\
       SQL 문자열 안에서는 정규식의 `'`를 `''`로 쓴다.\
       나온 행에서 그 문자열이 태그를 여는 `<`와 그 태그를 닫는 `>` 사이에 있으면 미통과다.\
       `&colon;`·`&#`도 검색하고, 나온 것이 `href`·`src` 같은 URL 속성 값 안에 있으면 그 값의 엔티티를 풀고 탭·줄바꿈과 앞뒤 공백·제어 문자를 뺀다.\
       그 값이 `javascript:`처럼 정해 두지 않은 스킴으로 시작하면 미통과다.
- **근거**: ASVS 1.1.1, 1.3.1, 1.3.5 / 행안부: 크로스사이트 스크립트
