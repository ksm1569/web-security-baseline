# FE-01 브라우저 코드가 사용자 값을 HTML이나 URL로 해석되는 자리에 그대로 넣지 않는가

- **적용**: 공통
- **위험**: 공격자가 만든 링크의 검색어나 `#` 뒤 값, 게시글 제목이 `innerHTML`로 화면에 들어가거나 프로필 홈페이지에 넣어 둔 `javascript:` 링크를 누르면, 그 사용자의 브라우저에서 스크립트가 실행되어 그 사용자 권한으로 글을 쓰거나 설정을 바꾸고 화면의 개인정보를 가져간다.
- **기준**: 개발자가 정한 고정 문자열이 아닌 값을 브라우저 코드로 화면에 넣을 때 아래를 지킨다.\
  URL의 쿼리와 `#` 뒤, API 응답, `postMessage`로 받은 값, `localStorage`에 저장한 값이 모두 여기에 든다.
  - 글자로 보여 줄 값은 `textContent`나 프레임워크의 기본 출력(Vue `{{ }}`, JSX `{}`)으로 넣는다.\
    HTML 문자열을 이어 붙여야 한다면 값마다 HTML 이스케이프를 한 뒤 잇는다.\
    `onclick` 같은 이벤트 속성 안에는 값을 이어 붙이지 않는다.\
    값은 `data-` 속성에 넣고 이벤트는 `addEventListener`로 붙인다.
  - HTML로 보여 줘야 하는 값은 DOMPurify 같은 HTML sanitizer를 거친 결과를 넣는다.\
    서버가 [BE-OUT-02](../backend/BE-OUT-02.md)대로 거른 필드를 브라우저에서 고치지 않고 넣는 것은 BE-OUT-02 점검 기록에 그 필드가 통과로 적혀 있을 때 인정한다.\
    브라우저에서 마크다운을 HTML로 바꾼다면 바꾼 결과를 거른다.
  - `href`·`action`·`location`·`iframe`의 `src`처럼 이동하거나 문서를 여는 주소는 스킴이 `http:`·`https:`처럼 정해 둔 것인지 확인한다.\
    `new URL(값, location.href)`로 해석해 `protocol`을 비교하거나, 맨 앞이 `/`·`https://`처럼 스킴을 바꿀 수 없는 문자열인지 본다.\
    해석에 실패하면 그 값을 쓰지 않는다.\
    문자열로 만든 HTML 안의 주소도 같다.
  - `<script>`의 `src`처럼 스크립트를 불러오는 주소는 `new URL(값, location.href).origin`을 정해 둔 출처 목록과 비교한다.\
    앞부분을 고정한다면 `https://cdn.example.com/`처럼 호스트 뒤의 `/`까지 고정한다.
- **하지 말 것**:
  - `<script>alert(1)</script>`를 넣어 보고 창이 뜨지 않으니 안전하다고 판단하기.\
    `innerHTML`로 넣은 `<script>`는 실행되지 않지만 `<img src=x onerror=alert(1)>`는 실행된다.\
    jQuery `.html()`·`.append()`로 넣으면 `<script>`도 실행된다.
  - 줄바꿈이나 검색어 강조를 보여 주려고 원래 값에 `<br>`·`<mark>`를 끼워 `v-html`·`innerHTML`에 넣기.\
    원래 값에 든 태그도 함께 살아난다.\
    줄바꿈은 CSS `white-space: pre-line`으로 보여 주고, 강조는 값을 이스케이프한 뒤에 끼운다.
  - HTML 이스케이프만 하면 된다며 `onclick="view('값')"` 안에 값을 이어 붙이기.\
    브라우저는 속성 값의 `&#39;`를 먼저 풀고 JS로 실행하므로 `');alert(1);//`가 그대로 실행된다.
  - jQuery에서 `.html()`만 피하기.\
    `.append()`·`.prepend()`·`.after()`·`.before()`·`.replaceWith()`에 넘긴 문자열에 `<`가 있으면 HTML로 해석된다.\
    `$()`도 앞 공백을 뺀 맨 앞이 `<`인 문자열은 HTML로 만든다.
  - 서버가 준 값이니 안전하다며 API 응답을 그대로 `v-html`·`dangerouslySetInnerHTML`에 넣기.\
    서버가 거르는 것은 BE-OUT-02 대상인 에디터 본문 같은 필드뿐이다.\
    글 제목, 회원 이름, 외부 API 값은 사용자가 넣은 글자가 그대로 온다.
  - URL에 `javascript`라는 글자가 있는지 찾아 막기.\
    `indexOf('javascript')`처럼 글자를 찾는 검사는 `JavaScript:`처럼 대소문자를 섞거나 중간에 탭을 넣으면 지나간다.\
    `startsWith('javascript:')`처럼 맨 앞을 보는 검사는 앞에 공백만 넣어도 지나간다.\
    Vue의 `:href`도 `javascript:` URL을 걸러 주지 않는다.
- **확인 방법**: 아래 단계에서 미통과가 하나라도 나오면 이 항목은 미통과다.
  1. 소스 코드에서 HTML 삽입 API를 찾는다.\
     `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `setHTMLUnsafe`, `document.write`, `createContextualFragment`, `DOMParser`, `srcdoc`, `v-html`, `dangerouslySetInnerHTML`, Svelte `{@html`, Lit `unsafeHTML`, Handlebars `{{{`, lodash `_.template`의 `<%=`가 대상이다.\
     jQuery는 `.html(`·`.append(`·`.prepend(`·`.after(`·`.before(`·`.replaceWith(`·`$(` 중 문자열을 넘긴 곳을 본다.\
     Angular는 `[innerHTML]`을 자체로 거르므로 그 검사를 끄는 `bypassSecurityTrust`를 찾는다.\
     `.js` 파일뿐 아니라 JSP 같은 서버 템플릿 안에 쓴 `<script>`도 찾는다.\
     소스가 없으면 빌드 산출물에서 위 목록을 찾는다.\
     Vue는 `innerHTML:`, React는 `{__html:` 형태로 찾아야 프레임워크 내부 코드가 아니라 앱이 쓴 곳만 걸린다.\
     source map(`.map`)이 있으면 그것으로 원래 소스를 본다.
  2. 찾은 곳마다 넣는 값이 어디서 오는지 따라간다.\
     개발자가 정한 고정 문자열이면 통과다.\
     아니면 다음 중 하나라도 해당할 때 미통과다.
     - 글자로 보여 주면 되는 값을 HTML 이스케이프 없이 넣거나 이어 붙인다.
     - `onclick` 같은 이벤트 속성 안에 값을 이어 붙인다.\
       HTML 이스케이프를 했어도 미통과다.
     - HTML로 보여 줘야 하는 값을 sanitizer 없이 넣는다.\
       서버가 BE-OUT-02대로 거른 필드는 BE-OUT-02 점검 기록에 그 필드가 통과로 적혀 있을 때만 통과로 본다.
     - sanitizer 설정이 `on`으로 시작하는 속성, `script`, 제한 없는 `iframe`을 허용하거나 URL 스킴 제한을 푼다.\
       DOMPurify라면 `ADD_ATTR`·`ADD_TAGS`·`ALLOWED_ATTR`·`ALLOWED_TAGS`·`ALLOWED_URI_REGEXP`를 본다.
     - sanitizer를 거친 뒤 디코딩하거나 `&lt;`를 `<`로 되돌려서 넣는다.
     - 마크다운을 HTML로 바꾸기 전의 원문만 거르거나, 바꾼 결과를 거르지 않는다.
  3. 소스 코드에서 값이 URL로 들어가는 곳을 찾는다.\
     `location =`·`location.href`·`location.assign`·`location.replace`·`window.open`, 요소의 `href`·`src`·`action` 대입과 `setAttribute`, jQuery `.attr('href'`·`.attr('src'`·`$.getScript(`, 동적 `import(`, Vue `:href`·`:src`, JSX `href={`·`src={`가 대상이다.\
     이동하거나 문서를 여는 주소에서 기준대로 스킴을 확인하지 않으면 미통과다.\
     `indexOf('javascript')`나 `startsWith('javascript:')`처럼 글자를 찾는 검사만 있어도 미통과다.\
     React 19 이상의 JSX `href`·`src`·`action`·`formAction`은 React가 `javascript:` URL을 막으므로 이동하거나 문서를 여는 주소로는 통과로 본다.\
     `<script>`의 `src`는 React가 다른 출처를 막지 않으므로 출처 확인이 그대로 필요하다.\
     스크립트를 불러오는 주소에서 출처를 기준대로 확인하지 않으면 미통과다.
  4. 브라우저에서 직접 넣어 본다.\
     이 항목은 브라우저가 만든 결과를 보므로 응답 원문이 아니라 개발자 도구 Elements 탭과 Console로 판단한다.\
     페이지 HTML 응답 원문에서 `<script>` 밖에 넣은 값이 태그 그대로 있으면 서버가 그린 자리이므로 BE-OUT-01·BE-OUT-02에서 본다.\
     저장해서 시험한 값은 점검이 끝나면 지운다.
     - 글자로 보여야 하는 자리: URL의 쿼리나 `#` 뒤 값, 또는 자동완성·알림 목록·토스트·모달처럼 JS가 그리는 곳에 나오는 글 제목이나 이름을 `"'><b>x</b>`로 바꾼다.\
       Elements에 `b` 요소가 생기면 미통과다.
     - HTML을 살려 보여 주는 자리: `<img src=x onerror=alert(1)>`를 넣는다.\
       넣은 값에서 생긴 요소에 `onerror`가 남아 있거나 alert 창이 뜨면 미통과다.\
       Console에서 `document.querySelector('[onerror]')`로 찾을 수 있다.
     - URL로 쓰이는 자리: 로그인 뒤 돌아갈 주소 같은 URL 파라미터와 프로필 홈페이지 같은 저장 URL에 `JavaScript:alert(1)`을 넣는다.\
       링크라면 Elements의 `href`가 대소문자와 상관없이 넣은 값과 같을 때 미통과다.\
       Angular처럼 앞에 `unsafe:`가 붙었거나 React 19처럼 다른 값으로 바뀌었으면 통과다.\
       바로 이동하는 곳이라면 alert 창이 뜨거나, 그 이동을 시험할 때 Console에 CSP가 `javascript:` 실행을 막았다는 오류가 나오면 미통과다.
